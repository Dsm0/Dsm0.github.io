nuPG 2024 browser manual

A practical guide to the WebAssembly and AudioWorklet browser implementation of the nuPG 2024 tool. This document describes what the browser application actually does. It is not a manual for the separate nuPG 2026 engine.

Use the browser's native Find command (Ctrl/Cmd+F) to search this page. For manual-only printing or unscaled reading, open the full-page manual in a new tab, then use the browser's Print command. The contents links below are ordinary links and work when this page is shown in the application's manual window.

1. Start safely

Serve the application from https:// or localhost with cross-origin isolation. The supplied Vite development and preview servers set the required Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Embedder-Policy: require-corp headers. A file:// launch or an ordinary static host without those headers cannot provide the SharedArrayBuffer, AudioWorklet, WebAssembly, and OPFS facilities used here.

  1. Set your system and browser volume low. There is no automatic normalization, limiter, or undo.
  2. Choose the output channel count (1–32) and click Enable audio in the host strip. This must be a user gesture. The channel count is fixed until reload.
  3. Select train 1 in nuPG 2022. The application starts with three independent trains and normally two output channels.
  4. In _pulsaret waveform, choose a library waveform. In _envelope, choose a library envelope such as Hann48.wav. The compact L action can instead load a local WAV or AIFF file.
  5. Press [n] in _train control. A loaded waveform and envelope give the first audible grain. Untouched startup audio buffers can be silent even though their editable CV arrays display ramps; drawing or loading a waveform/envelope before enabling audio is remembered and uploaded when audio starts.
First preset warning. The adapted nuPG26_01_2024-adapted bank has a 1 Hz fundamental in slots 0–5. It produces separated pulses rather than a continuous tone. Try bank 02 or slot 6 for a quicker continuous-sounding start.

There are three practical first-sound routes: load a bundled waveform and envelope as above; load a preset bank and recall a slot (bank 02 or adapted bank 01 slot 6 is a quick starting point); or, at low volume, press Rand in each waveform/envelope panel and then press [n]. Rand is intentionally not level-safe, so reduce amplitude before randomizing and save a preset first if needed.

The three ACTIVATE buttons in _groups control activate table-driven group factors. They are not group mute buttons. A group can be active while its amplitude is zero, or inactive while its direct main controls still produce sound. Use the main amplitude controls or the mask controls when you need level or density changes.

2. How sound is made: signal flow

Think of nuPG as a machine that fires tiny shaped sound packets. Each packet, or grain, reads the pulsaret waveform through an envelope. Slow repetition gives separate clicks or pulses; faster repetition can merge into a pitched buzz or a continuous texture. The sound depends both on when packets begin and on what happens inside each packet. These are related, but they are not the same control.

A train is one complete pulse generator. Each train feeds three parallel groups from a shared pulse clock, waveform, and envelope. The groups have separate formant ratios, dilation, amplitude, pan, and trigger offsets. The application mixes three independent trains: selecting another train changes which train you edit, not which trains can be heard.

The boxes describe different jobs, not a chain of three oscillators feeding one another. Groups run in parallel. The DC blocker removes persistent offset from the signal; it is not an adjustable tone filter or a limiter. Tables and modulators steer the timing, grain, and level controls rather than acting as extra audio channels in this diagram.

Inside one grain: waveform × envelope

The pulsaret waveform supplies the rapid variation inside the packet: a smooth waveform, a complex harmonic shape, or a noise-like texture. At every new grain, reading starts at the beginning of this table. The waveform can wrap within the grain, so a longer grain can contain several traversals. Loading a file supplies table samples; it does not play the whole file at its original duration.

The envelope is a second table multiplied into that waveform over the grain's lifetime. A tapered envelope softens the beginning and end; an abrupt envelope can add sharper transients and a broader spectrum. It is a window over each grain, not a keyboard note's ADSR. An all-zero waveform or envelope silences the grain. This is why both startup audio buffers must be populated.

Formant ratio controls how quickly the waveform is read and also contributes to the grain's nominal duration. Envelope dilation changes how quickly the envelope is traversed without directly changing the waveform's read speed. Increasing dilation makes the packet shorter; decreasing it makes it longer. The formant control is not a filter cutoff or an independent oscillator frequency in Hz.

Three useful quantities: pulse spacing, waveform rate, grain length

For a simple starting case, use positive dilation, neutral table factors, no matrix or rate/flux modulation, and no skipped pulses. Let F be the main fundamental in Hz, R one group's formant ratio, and D its dilation:

  • Time between pulses: approximately 1 / F seconds.
  • Waveform-table traversals per second: approximately F × R.
  • Length of each grain: approximately 1 / (F × R × D) seconds.

With a single-cycle waveform, the table-traversal rate is its nominal within-grain frequency. A table containing several cycles or noise does not have that simple pitch interpretation. The perceived pitch and spectral emphasis of the whole pulse train also depend on repetition, envelope shape, and masking; “400 table traversals per second” does not guarantee a perceived 400 Hz note.

This explains a useful distinction: raising the main fundamental speeds up both repetition and waveform reading, whereas raising a group's formant ratio changes that group's packet without speeding up the shared clock. Lowering dilation lengthens the packet without slowing its waveform. In this simple case, a grain spans approximately 1 / D waveform-table traversals.

Overlap is a consequence of those timings. At F = 100, R = 4, D = 0.1, a grain lasts about 25 ms while another begins every 10 ms: several grains in the same group coexist. Longer windows and overlapping groups can make a texture denser and louder. At D = 1 the 2.5 ms grain leaves a gap before the next pulse. This comparison is about window duration; the actual audible region depends on the envelope shape. Keep level low, and use positive dilation for these experiments. Sample rounding and the engine's four-sample minimum affect very short grains.

Rhythm, density, level, and space are different controls

  • Probability, burst/rest, and sieve skip trigger opportunities. They change the pattern or density of new grains, not the waveform's shape. A rejected trigger does not cut off grains already ringing. Probability 0.5 averages about half the opportunities before the other masks; it is not a half-volume setting.
  • Amplitude scales the group's sound, including overlapping grains. Use amplitude zero to silence a group, not its ACTIVATE button. More groups or trains add energy; their sum can clip even when each amplitude control is below one.
  • Pan places new grains across the output channels. Channel masking contributes an additional repeating placement pattern; it is not another waveform or a level control. Existing grains keep the pan assigned at their birth, so long grains can outlast a pan change.
  • Group offset delays that group's trigger by up to one second. It staggers the three layers without changing their formant ratios or shifting their control-table drawings.

Two kinds of tables, and two kinds of time

Waveform and envelope tables describe one grain. Their horizontal axes mean position within a waveform cycle/table or within a grain's envelope. The other visible tables describe control changes across a train traversal. Their horizontal axes are positions in the automation sequence. A drawn curve is not another audible oscillator: its values are mapped through its min/max pair and applied as control factors while loop, one-shot, or scanner tasks read it.

_dur sets the automation traversal time in seconds. It does not set an individual grain's length; formant and dilation do that. The scanner moves through this control trajectory, not through a recording of the output. The waveform's internal wrapping is also separate from the preserved control-table endpoint failure.

For an activated group, its formant, dilation, and amplitude table factors multiply their main controls; its pan table adds an offset to main pan. For example, main formant ratio 4 with mapped formant-table factor 0.5 gives a ratio contribution of 2. A raw drawn height is not yet that factor: the range pair performs the mapping, and a descending pair reverses the curve's effect. ACTIVATE enables these four group factors; it does not start or mute a voice.

An important asymmetry: the main fundamental F is shared by pulse and formant calculations, but the fundamental table changes the pulse-clock branch, not the F used in each group's base formant calculation. A fundamental-table sweep can therefore change spacing and overlap without the same change in waveform rate that moving the main fundamental causes. Fundamental matrix modulation is likewise on the pulse-clock branch. Group formant tables and formant matrix routes act on the grain branch.

Fundamental, probability, rate-modulation, and flux tables are train-wide and do not wait for a group's ACTIVATE button. Also, switching loop off does not necessarily restore every neutral factor because some source reset omissions are retained; see transport behavior before assuming a previously sequenced patch matches the simple equations above.

Where modulation fits

The four modulator editors and matrix provide moving control signals. Frequency sets how quickly a modulator evolves; depth sets its influence; the matrix chooses destinations. Fundamental routes perturb the clock, formant routes perturb group rate and duration, amplitude routes affect level, and pan routes affect placement. A modulator is not heard as a separate fourth voice. The stored envelope routes are inactive in this source implementation.

Rate modulation amount, ratio, and mode act on the grain's waveform read-rate path, including a saw-derived value held from triggers. They can change how much waveform fits inside a packet without a matching change to its envelope duration. They are separate from the four-source matrix, not ordinary sine-FM oscillator controls. Multiparameter modulation (flux) adds stochastic variation to pulse timing and group waveform rates; it is a way to loosen regularity, not a master amount for every matrix route. Once these paths are active, the simple timing equations are a starting model rather than a complete prediction.

Hear the relationships one at a time

  1. Save your current patch. On a fresh, otherwise unmodified train, load a simple waveform and a tapered envelope, set group 1 amplitude low and groups 2/3 amplitudes to zero. Keep group activation off, modulation amounts at zero, and masks at their unskipped defaults.
  2. Set main fundamental to 100, group 1 formant to 4, and dilation to 1, then press [n]. Change only formant between 2, 4, and 8: the packet's internal rate and length change while the pulse clock stays fixed.
  3. Return formant to 4 and compare dilation 0.5, 1, and 2. Listen for changes in packet width and spectrum, not a new pulse rate. Then compare main fundamental 50, 100, and 200 to hear the coupled change in repetition and packet rate.
  4. Reduce probability in _masking. Compare missing packets with simply reducing group amplitude. Finally bring in a second group quietly, with a different formant and pan, to hear parallel layers sharing the same pulse pattern.

For exact ranges, use Parameters and ranges; for evolving patches, continue to Practical sound-design workflows.

3. Desktop, trains, and windows

The page reproduces the source desktop as a set of floating in-page windows. The browser exposes the 56 source windows through Windows…; the top-bar Manual button, or the nuPG — User manual entry in Windows…, opens this additional help window. The manual window is draggable and hideable like the other windows and preserves its reading position when hidden and reopened. Window title bars can be dragged; clicking a window brings it to the front. The close button hides a window without destroying its state. Fit scales the 1660 × 1040 source desktop to the viewport. Fixed zoom choices preserve source geometry and may require scrolling. On a narrow page, zoom out or use the full-page link above for reading and printing; printing the application page itself is not the manual-only print surface.

Resize the manual by dragging its bottom-right corner beside the Resize label. Both width and height change, and the document reflows inside the window. Hiding and reopening keeps the chosen size and reading position for this page session. The original instrument panels keep their source-sized layout.

In scrub mode, loop sequencing stops and the task samples group factors from the scanner position about every 50 ms. Drag the scanner slider or enter a value in its numeric field. A value is clamped to 0–2047 and sent to the selected train. The disabled scanner S button is intentionally inactive: source scanner synchronization/FUN callbacks were not ported.

The scanner's R button cycles gesture states: idle, record, replay, idle. While recording, the position is captured at 10 ms intervals, up to about 1,000 seconds of history. Releasing the scanner slider while recording automatically changes to replay; the recorded drag then plays. Replay cycles until stopped. If storage fills, or replay is requested with no recorded gesture, the footer reports the error.

Preserved 2048 endpoint behavior. A 2048-value loop sequence still attempts index 2048. The footer reports the endpoint error, audio continues with the last valid factors, and the loop indicator remains enabled. Reverse traversal starts at that invalid endpoint and fails immediately. The browser does not wrap, pad, or repair this case. A valid 2049-value sequence retains its extra endpoint. Do not treat a still-lit loop indicator as proof that the endpoint was repaired.

ACTIVATE gates only a group's table-driven formant, dilation, amplitude, and pan factors; it is not a mute. Direct main controls remain effective while a group is inactive. Fundamental, probability, rate-modulation, and flux loop factors are train-wide and are not gated by group activation. Stopping a loop intentionally leaves group 2's formant factor and the FM/flux loop factors untouched, matching the source omission.

The transport, activation flags, scanner state, gesture history, sieve-enabled flag, modulation mode, and recording state are runtime state; they are not the same thing as the editable train values saved in a preset.

Table CV data is always represented in the −1…+1 domain, but its min/max controls define how that data is interpreted by a consumer. Separately, a short CV upload or paste can leave the remembered audio-buffer tail untouched. Compact loading and library/editor loading intentionally use different sample counts; no browser sample-rate conversion substitutes for these operations.

S on a waveform or envelope saves the actual 2048-sample audio buffer as WAV or AIFF. Other tables are padded/truncated to 2048 for saving. The save dialog also offers save user, which stores a named table in IndexedDB. Download important work: browser-origin storage is profile-specific, can be cleared or quota-limited, and does not survive every private browsing or profile lifecycle.

6. Parameters and ranges

Sliders are displayed in normalized slider space but the adjacent number field accepts physical values. Values are constrained to the ranges below, with exponential mapping for frequency controls marked “exp.” Steps are the source control steps. All ordinary values are train-scoped unless a group is named. Fundamental is the shared train pulse rate; each group's formant is a ratio of that fundamental, not an independent Hz oscillator. Nominal grain duration is approximately 1 / (fundamental × formant ratio × dilation) (with engine minimum-duration and rate-modulation details), so increasing dilation shortens the envelope traversal and decreasing it lengthens it.

7. Randomization

One panel: Rand

Rand is available on all 49 sound panels: the 19 compact table panels, their 19 enlarged editors, _main, _modulators, the four individual modulator editors, _masking, _groupsOffset, FOURIER, SIEVES, and the modulation MATRIX. It affects only the current panel and selected train.

  • Scalar controls use their existing physical ranges, frequency mapping, and steps.
  • Tables retain their length and min/max settings. Control tables become smooth random curves; pulsaret tables become normalized random harmonics; envelopes are nonnegative curves that taper to zero at both ends. An empty table is filled at its standard length.
  • Waveform and envelope edits update their audio buffers immediately when audio is running, or on Enable audio when audio is not yet running.
  • FOURIER randomizes its harmonic bars and generated waveform. SIEVES creates a union of four random periodic sieves and applies the mask without changing whether sieve mode is enabled.

Other panels, other trains, table ranges, the internal clipboard, saved presets, transport, group activation, modulation mode, scanner state, recording, window layout, and train selection are untouched. Utility/navigation panels do not have Rand. Randomization is destructive to the selected panel; store a preset first if you may want the old values. Start quietly: random amplitude, waveforms, and modulation can produce a large level change.

Whole selected train: Rand All and Rand All File

The top bar places Rand All and Rand All File immediately to the right of Manual. Both target the train selected when clicked, even if you switch to another train before loading finishes.

  • Rand All applies every sound-panel randomizer described above, including hidden panels, all 19 tables, main parameters, modulation, the matrix, masking, offsets, Fourier, and sieves. Each compact/editor pair shares one table randomization. Existing table lengths and min/max ranges are preserved.
  • Rand All File makes an independent random WAV selection for each of the 19 tables and loads it through the normal library path. Both selectors in each compact/editor pair show the same selected file. Only table data and waveform/envelope audio buffers change; scalar parameters, Fourier, and sieves remain unchanged. WAV filename rules match Rand file, and different tables may receive the same file.

Neither button changes other trains, transport, group activation, modulation mode, scanner state, recording, clipboard, saved presets, or window layout. Both global buttons stay disabled until the active batch finishes. A failed file load is reported in the footer while the other table loads are still attempted. These actions replace the current working patch, not the stored presets: save a preset first and keep listening volume low.

8. Modulation and the matrix

Rate and multiparameter modulation

The _modulators panel exposes _rate modulation amount (0–16), _rate modulation ratio (0–16), and _multiparameter modulation (0–2), plus buttons for the three corresponding control tables. Rate modulation uses the hidden frequency buffer (initially ones) and changes the rate/latch path; it is not conventional sine FM with a visible frequency editor. Multiparameter modulation is shared stochastic flux that perturbs pulse and group formant rates, not generic all-parameter modulation. Source loop factors shape these paths and are not all applied uniformly once.

The mode button alternates mode -> samp+hold rm and mode -> rm. The mode controls how the latched saw-derived modulation is selected at control-block boundaries. It is runtime state and is not a group activation or mute.

Four modulator editors

_m1 through _m4 each have a type, frequency, and depth. Frequency is 0.001–150 Hz, depth is 0–10 in integer steps (the source label is misleading; this is depth), and type is 0–4:

Matrix destinations and inert routes

The 13 destination rows are _fundamental, _formant_01, _formant_02, _formant_03, _env_01, _env_02, _env_03, _pan_01, _pan_02, _pan_03, _amp_01, _amp_02, and _amp_03. Each row has four toggle cells for the four modulators. Fundamental, formant, pan, and amplitude destinations are wired. The three envelope destinations are source-declared but inactive: their cells can retain and display a stored value, but enabling them does not create new envelope DSP.

Cell source names such as mXY are not a reliable visual destination coordinate. The source's clump(13) binding scrambles nominal order: the effective modulator is floor(flatIndex / 13), and the effective destination is flatIndex % 13. The UI displays effective rows and gives inactive cells an explanatory title. Use the visible row and modulator headers rather than guessing from a key name.

Matrix toggles are per-train preset values. Modulator type/frequency/depth and active matrix flags are train-scoped. They do not automatically alter other trains.

9. Fourier generation and sieves

FOURIER

The FOURIER editor has 16 harmonic bars. Drag a bar from zero to one; the generated 2048-sample waveform is normalized by the source sine-fill operation and stored as the hidden fourier sequence. Focus its canvas and press C to put the generated waveform on the internal clipboard; P or Ctrl/Cmd+V pastes clipboard data back through the Fourier path. Use a table's paste to move the resulting waveform into pulsaret when desired. Fourier is a UI generator, not a separate engine control. Its Rand button randomizes all 16 bars and regenerates the waveform.

SIEVES

The SIEVES window has definition text, logical-operator text, an output mask, segmentedBinaryMask, sequentialBinaryMask, and sieveAsTable. Put the cursor on the operator line to evaluate. Press Enter to evaluate that line; Shift+Enter inserts a new line. The selected mode converts the point intervals to a binary sequence, writes sieveSize and up to 100 model values (the active engine consumes the first 16), and enables the sieve. Clicking the already-active mode disables it. sieveAsTable copies a 2048-sample visualization of interval lengths to the internal clipboard; it does not enable the sieve by itself.

The parser accepts whitespace and // or /*…*/ comments; variable assignments such as ~size = 16;; numbers, negative integers, parentheses, backtick references, and the operators | union, & intersection, - difference, -- symmetric difference, numeric +, *, /, %, and sieve shifts >>/>>!. Binary operators have equal precedence and associate left to right. Supported constructors are Sieve(...), Sieve.new, Sieve.union, Sieve.sect, Sieve.symdif, and Sieve.dif, with the source suffix forms _o, _i, and _oi for offset/limit variants. Constructor limits default to 65536 and parser-generated point/mask results are bounded at 1,000,000 points/samples.

Constructor bases and offsets must be safe integers; bases are positive. An expression must produce a sieve, not merely a number. Errors include a character offset and are reported instead of executing text. The model can hold up to 100 sieve values, but the active source graph consumes the first 16. A compact starting example is:

~size = 16;
~a = Sieve(3, `~size);
~b = Sieve(5, `~size);
~a|~b

Enter the final ~a|~b line with the cursor on it, then choose segmented or sequential mode to apply it.

10. Preset banks and interpolation

The preset system reads legacy SuperCollider literal banks as data, not executable code. It preserves physical keys, normalized preset arrays, keyed historical rows, and diagnostics. Malformed or unsupported rows are reported; they are not silently repaired or executed.

Library and bank workflow

  1. Choose a bundled entry in the Preset library menu, or choose open bank file… for a local .scd/.txt bank. The selected bank belongs to the current train.
  2. Loading parses the bank and applies its saved physical bank state. The displayed index is set to slot 0, but that does not generally mean preset 0 has been recalled; explicitly select Current preset 0 or the preset 0 menu entry to recall it. The two adapted banks intentionally align their initial state with slot 0.
  3. Use + to append the current state and − to remove the selected slot. To replace a slot, choose the menu action store current preset. Slot numbering is zero-based.
  4. Choose the menu action load user bank… to reload a named user bank. Set a bank name and choose SAVE to save it to the browser's user-bank IndexedDB library and download its SuperCollider literal text. Keep a downloaded copy for portability.
  5. Use the two preset fields around the interpolation slider to choose from/to slots. The slider runs 0–1 and interpolates normalized CV values. Exponential frequency controls are interpolated in their normalized specification, so their physical result follows the exponential mapping.
  6. Open selected interpolation keys… and enter comma-separated source keys to restrict interpolation. Blank means all keys. This is useful for morphing timbre while holding transport-related workflow decisions outside the bank.

Presets contain the 158 preset keys in source order, including array values, but runtime playing/monitor state, activation flags, loop state, one-shot activity, playback direction, scrub mode and gesture history, sieve-enabled flag, modulation mode, recording, and window layout are runtime concerns. A preset load updates train values and the waveform/envelope buffers; it does not infer missing nuPG 2026 controls.

Bundled banks

The browser includes 34 bundled banks: 32 original 2024 banks (124 usable prior-corpus slots) plus two adapted banks containing nine additions, for 133 usable preset slots in total. The additions are:

These are 2024-engine adaptations, not a nuPG 26 engine port. Physical controls were converted to the existing normalized Conductor-bank format; source waveforms and control-table lengths retain their order. Overlap tables map to envelope-dilation tables, the 13 main controls retain positional mapping, and range-pair order and effective matrix destinations are retained. Missing controls use 2024 defaults. The source fractional default sieve sequence is quantized to the 2024 binary sieve specification, while its explicit binary pattern is retained. Separate 2026 spatial controls, synthesis mode, transport flags, and activation flags are not applied or inferred. No OscOS support or exact nuPG 26 audio parity is claimed.

11. Recording

Enable audio first, then open _record. Choose aiff, wav, or caf, enter a base filename, and press RECORD; press STOP to finish. The recorder captures the configured discrete output bus count at the engine sample rate and encodes 24-bit PCM: AIFF and CAF use big-endian integer PCM, WAV uses little-endian integer PCM.

_DIR uses the browser directory picker when available and writes the completed file there. If directory access is unavailable, the browser downloads the result when recording stops. Recording itself requires OPFS; a missing OPFS implementation is an error, not a download fallback. Temporary OPFS storage is used by the recorder worker while recording; the completed download is detached before temporary storage is removed. A browser may deny OPFS, picker, download, or quota access.

Recording does not normalize or limit playback. The summed float engine output can exceed nominal −1…+1; finite out-of-range samples saturate only at the 24-bit container endpoints, while non-finite samples are rejected. Leave headroom and watch the footer for recording errors. The recorder is not a mastering stage.

Each group can hold up to 2047 active grains under the preserved engine admission rule; denser settings reject additional grain spawns. The host status exposes live-grain activity, and recording errors are reported in the footer.

The audio engine supports 1–32 configured output channels, but the physical browser destination and hardware may expose fewer channels. There is no automatic surround-to-stereo fold-down. A recording retains the requested bus count and may therefore be multichannel even when your monitoring device is not.

12. Practical sound-design workflows

Build a stable first patch

Load a clean waveform and a tapered envelope, press [n], then set fundamental frequency around 80–200 Hz, one formant ratio between 2 and 8, dilation near 1, and one amplitude below .5. Keep groups 2 and 3 at low amplitudes while establishing a level. Activate group 1 only after you understand the table factors. Save a preset before exploratory edits.

Make a moving formant texture

Open group 1 from nuPG 2022, draw a slow curve in formantFrequencyOne, set its min/max to the desired factor range (the result multiplies the direct formant ratio), press loop, and activate group 1. Draw a complementary pan curve and a narrower amplitude curve. Use group offset 2 or 3 to stagger another group's trigger, not to shift a table or pan. If a 2048-sample sequence reaches its endpoint, see the endpoint warning. The loop duration controls how quickly these curves are traversed.

Shape density without changing pitch

Use _masking: probability controls coin acceptance, burst/rest creates runs and gaps, channel/channelCenter distribute accepted events, and the sieve selects or rejects positions in the delayed counter. Change one mask stage at a time. A probability of 0 can make a healthy patch appear silent; a sieve enabled with a sparse sequence can do the same.

Use modulation deliberately

Choose one modulator, keep depth low, route it first to a formant or pan row, and listen. Then add the rate amount or multiparameter amount. Use the corresponding amount/ratio/flux table for a slow macro-shape. If a matrix cell appears to do nothing, check that it is not one of the three inactive envelope rows and that the destination's base amplitude or amount is nonzero.

Compare trains

Use one train for a dry reference, another for a randomized variation, and the third for a preset interpolation. Select trains from nuPG 2022; do not assume a table edit or preset load propagates. Record each result with an explicit filename and channel format.

Preserve experiments

Store a preset before Rand, download banks and important tables, and keep a browser-profile backup. There is no undo. Reloading the page reconstructs default train state and can lose unsaved window, table, and user-library work.

13. Troubleshooting, compatibility, and non-features

SymptomCheck
No sound after pressing [n]Enable audio, load both waveform and envelope, and check amplitude, probability, mask, and group activation. The initial audio buffers can be silent even when CV arrays display data.
Loop appears stuck at an endpointRead the footer. For a 2048-value sequence this is the preserved index-2048 failure: factors remain at their last valid values, audio continues, loop stays flagged, and reverse fails immediately. Do not wrap or pad it as a “repair.”
Only one group changesEach group has independent ACTIVATE state and four independent table windows. ACTIVATE is not mute; use the group's amplitude or main control to silence it.
Preset looks different after loadingCheck zero-based slot number, selected train, selected interpolation keys, and the bank's diagnostic notice. Adapted nuPG26 banks use 2024 defaults where controls were missing.
File load sounds wrongWAV/AIFF are decoded as supported PCM formats, then the action's scalar sample count is resampled to 2048. Compact loads 2048; menu/editor loads 4096. Multichannel input is read as its interleaved scalar stream for the table action.
Recording cannot startEnable audio first and verify OPFS support and storage quota. If only directory-picker access is unavailable, recordings download on stop; there is no OPFS fallback. Check browser permission and the footer's recording errors.
Audio starts but browser suspendsResume from a user gesture, keep the tab active, and use localhost/HTTPS with the required isolation headers. Device latency and deadline scheduling remain browser constraints.
Modulation has no audible resultConfirm modulator depth and amount are nonzero, the intended matrix cell is active, and the destination is not an inactive envelope route.

Compatibility limits

  • Desktop Chromium is the exercised target. Safari, Firefox, mobile browsers, and multichannel hardware are not verified.
  • AudioWorklet, WebAssembly, SharedArrayBuffer, cross-origin isolation, and OPFS recording are required facilities.
  • The browser port has no MIDI, OSC, OscOS, neural synthesis, or automatic nuPG 2026 spatial/synthesis controls. It does not claim exact nuPG 26 parity.
  • There is no automatic normalization, limiter, undo, or persistent cloud library. Origin/profile storage may be cleared or quota-limited.
  • Source window geometry is reproduced in HTML; native macOS window chrome and OS file dialogs are not reproduced pixel-for-pixel.
  • Declared but inert source fields include ampLocalOne, ampLocalTwo, ampLocalThree, and frequencyModIndex; they are preset keys but have no active spec/consumer wiring. tableShift is range-configured but not consumed. progressSlider is UI-only. The enlarged-editor S and scanner synchronization S are visibly present but intentionally inactive.

When in doubt, trust the selected train color, the footer error notice, and the status strip rather than a stale window position or a highlighted control. Save and download work before clearing browser data or changing profiles.
